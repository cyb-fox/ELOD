# RUBRIC_判定口径 —— 全量推理日志审计

**你要回答的问题是：这段推理对不对？这个结论你认不认可？**

你完全不知道（也不要试图推断、不要联网检索）：这条日志对应哪个文件、属于某个  
漏洞修复对的哪一侧、真实标签是什么、真实 CWE 是什么、属于哪个项目。  
包里的别名 `L-XXXX` 是随机分配的，与上述任何信息都**没有**对应关系。

---

## 字段一：`verdict` —— 结论是否正确（三选一，**必填**）

| 值                  | 含义                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------- |
| `correct`          | 分析器给出的最终判定，与你自己读完材料后的判断一致。**包括**：它判未决（underdetermined），你也认为仅凭单文件确实定不了——这也算 `correct`。 |
| `too_conservative` | 分析器**过于保守**：它判了未决（或判了"无风险点"），但你认为证据其实已经足够支持一个确定的结论（报漏洞，或证明有防护）。                       |
| `too_aggressive`   | 分析器**过于激进**：它报了一个确定的漏洞结论，但你认为证据不足以支持它——这一步跨得太大。                                       |

**判定要点**

- 关键不是"最终答案对不对"，而是"**在这个证据水平下，这个结论是否站得住**"。
- 例：它报 vuln，证据确实支撑 → `correct`；它报 vuln 但引用的那行根本不涉及该风险 → `too_aggressive`。
- 例：它判未决，你也认为单文件定不了 → `correct`；它判未决但文件里明明有清楚的边界检查 → `too_conservative`。
- 拿不准时选你认为**更接近**的那一档，并在 `note` 里写清犹豫点。

---

## 字段二：`reasoning_agree` —— 推理链认可度（1–5 分，**必填**）

评估这条日志的**推理过程**质量，与结论对错分开打分：

| 分 | 含义                                     |
| - | -------------------------------------- |
| 5 | 推理链完整可信：每步都有据可依，义务状态流转与引用的证据一致，结论自然推出。 |
| 4 | 基本可信，个别步骤略简略但不影响结论。                    |
| 3 | 一半一半：主要步骤成立，但有明显跳跃或遗漏（例如漏掉一个应该检查的义务）。  |
| 2 | 推理薄弱：关键步骤缺乏证据支撑，或引用的内容与判断对不上。          |
| 1 | 推理不可信：步骤之间没有逻辑关联，或明显误读了它自己引用的代码。       |

**打分依据（请逐个对照）**

1. 每步的 `引证行` + `上下文源码`，是否真的支持该步的判断？
2. `义务 ...: A -> B` 的状态流转，有没有"从无到有"的凭空跳跃？
3. 最后一步 `arbiter` 的结论，能否从前面各步的义务状态**推出来**？
4. 有没有该检查却完全没提的义务（例如给了长度却不算边界）？

**注意**：`reasoning_agree` 与 `verdict` 相互独立。  
一条日志可以"结论正好蒙对但推理很烂"（`verdict=correct` + `reasoning_agree=1`），  
也可以"推理很严谨但过于保守"（`verdict=too_conservative` + `reasoning_agree=5`）。

---

## 字段三：`evidence_grounded` —— 引证是否落到实处（`yes` / `no`，**必填**）

只看一件事：**它引用的行和内容，是否真实存在、且与它那一步的判断相称？**

- `yes`：引用的行号与内容属实，且内容确实与那一步的判断相关。
- `no`：出现以下任一情况 ——
  - 行号指向的内容与它写的 `引证内容` 对不上；
  - 引用的内容存在，但和那一步的判断无关（张冠李戴）；
  - 该步完全没有引用任何具体位置，却下了确定判断。

若某条日志**没有任何引证**（例如零风险点的空轨迹），本字段填 `yes`  
（它没有做出无据的引证），并在 `note` 说明。

---

## 全部分类后，再补一个 `note`（≤140 字中文）

必须引用日志里的**具体**步号 / 行号 / 义务名（如 `步骤3`、`operator:18`、  
`arithmetic_bound`），不要写"看起来还行""感觉不对"这类空话。

---

## 输出格式（严格遵守，便于机器汇总）

把结果写到你被指定的 CSV（`打标表_评审A.csv` / `打标表_评审B.csv`），  
每行一个 `alias`，四个字段：

```csv
alias,verdict,reasoning_agree,evidence_grounded,note
L-0001,too_aggressive,2,no,"步骤1判 arithmetic_bound VIOLATED 但引证行18是运算符定义，未给分母来源"
```

- `verdict` ∈ {correct, too_conservative, too_aggressive}
- `reasoning_agree` ∈ {1,2,3,4,5}
- `evidence_grounded` ∈ {yes, no}
- `note` 中文，≤140 字

---

## 纪律

- **独立完成**：不要与另一位评审讨论、不要互看结论。两人之间的一致性本身是我们要测量的量。
- **禁联网**、禁检索 CVE / 漏洞库 / 项目名。
- **不可跳过**：870 条每条都要给出三个字段。拿不准也要判，并把犹豫写进 `note`。
- 少数条目会写「本条没有任何推理步骤」。这本身是一个**结论**（"该文件没有值得深究的  
  问题点"），照常给三个字段 —— 若你认为这是漏检，`verdict` 可填 `too_conservative`。
