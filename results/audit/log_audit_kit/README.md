全量推理日志审计   
你的工作是：**读它的推理过程，判断推理是否成立、结论是否可接受。**
===================================

## 你要做的

打开 `打标表_评审A.csv`（或 B），逐行填 `packets/L-XXXX.txt` 对应的三个字段。

## 三个字段（口径详见 RUBRIC_判定口径.md）

1. `verdict` —— 结论是否正确，三选一：  
   `correct` / `too_conservative` / `too_aggressive`
2. `reasoning_agree` —— 推理链认可度，1–5 分（5 = 完全认可）
3. `evidence_grounded` —— 引证是否落到实处：`yes` / `no`  
   （即：它引用的行和内容，真的支持它那一步的判断吗？）

## 纪律

- **独立完成**，不要与另一位评审讨论、不要互看结论。
- **禁联网**、禁检索 CVE / 漏洞库 / 项目名。
- 包里的别名（`L-XXXX`）是随机的，与文件真实身份、属于修复对的哪一侧、  
  真实标签**没有任何对应关系**，不要试图推断。
- **不可跳过**任何一条。拿不准也要给一个判断，并在 `note` 里写清犹豫点。
- `note` 请引用日志里的**具体**步号 / 行号 / 义务名，不要写空话。

## 关于"没有推理步骤"的条目

少数条目会写「本条没有任何推理步骤：分析器未定位到任何可疑点」。  
这本身就是一个**结论**（"这个文件没有值得深究的问题点"），  
请照常给出三个字段的判断。
